# V1 PRD 草案：오늘의 시그널 / Today’s Signal

## 1. 引言 / 概述

### 1.1 产品名称

**오늘의 시그널 / Today’s Signal**

### 1.2 产品类型

iOS 移动端 App

### 1.3 V1 一句话定位

**在韩语聊天截图学习助手的基础上，帮助用户继续追问不懂的表达、检查自己的韩语回复，并快速生成适合韩娱聊天语境的韩语回复建议。**

### 1.4 当前 MVP 状态

MVP 已完成核心功能：

* 上传截图 / 粘贴文本；
* OCR 识别聊天内容；
* 成功区分左右两个对话人；
* 用户选择 idol / 对方侧；
* AI 分析 idol 侧气泡；
* 输出中文翻译、生词、语法/词尾解释；
* 生成学习卡片；
* 本地保存卡片。

### 1.5 V1 背景

当前 MVP 已经解决了“看懂 idol 韩语聊天内容”的核心问题，但仍有几个明显缺口：

1. **学习卡片中的 AI 例句未实现**
   现有卡片可以保存知识点，但学习价值还不完整，需要补齐例句生成。

2. **用户无法继续追问解释结果**
   如果用户想问“这里为什么用 -는데？”、“这几条是不是要连起来看？”，目前没有反馈入口。

3. **系统尚未评价用户自己的韩语回复**
   OCR 已经能区分左右气泡，但选择 idol 侧后，目前只分析 idol 侧，没有检查“我”的回复是否自然。

4. **实时回复建议还未独立成路径**
   有些用户不是想深度学习，而是想快速生成一句自然韩语回复。这个需求不应该强绑定 AI Analysis 学习路径。

---

## 2. V1 目标 / Objectives

### 2.1 V1 核心目标

V1 的核心目标是：

> 从“看懂聊天”升级到“能追问、能回复、能检查回复、能更完整地沉淀学习卡片”。

具体包括：

1. **补齐学习卡片 AI 例句生成**

   * 生词卡片生成 1 条 AI 例句；
   * 语法/词尾卡片生成 1–2 条 AI 例句；
   * 例句需附中文翻译。

2. **新增 Feedback Chat**

   * 用户可以在 Analysis Result 页面底部统一追问；
   * 支持针对整段对话、某个气泡、生词或语法点继续提问；
   * V1 暂不支持将追问内容保存为新卡片。

3. **新增“同时检查我的回复”**

   * 在学习解析流程中，系统可以同步检查我方气泡；
   * 如果回复自然，显示自然评价；
   * 如果有问题，给出问题解析和更自然替代表达。

4. **新增快速回复建议路径**

   * 独立于学习解析；
   * 支持从首页快速进入；
   * 支持上传截图或粘贴文本；
   * 支持选择 idol 气泡、输入中文想表达的内容、选择回复语气；
   * 默认生成 3 条韩语回复建议。

## 3. V1 用户画像

### 3.1 核心用户

仍然是：

**K-pop / 韩娱粉丝中的初中级韩语学习者**

但 V1 会进一步覆盖两类更具体的使用动机。

---

### 3.2 用户类型 A：学习追问型用户

用户特点：

* 看完 AI 解析后仍有疑问；
* 想知道某个词尾为什么这样用；
* 想确认几条气泡是不是应该连起来理解；
* 想进一步理解语气、关系感或表达差异。

典型问题：

* “这里为什么用 -는데？”
* “这句话是撒娇语气吗？”
* “这几条气泡是不是连起来看？”
* “这个词和另一个词有什么区别？”

---

### 3.3 用户类型 B：实时回复型用户

用户特点：

* 想快速回复 idol / bubble / DM；
* 可能不想完整走学习解析流程；
* 有时知道自己想表达的中文意思，但不会自然写成韩语；
* 想根据不同语气生成多种版本。

典型需求：

* “我想回复一句自然一点的韩语。”
* “帮我用可爱语气说：今天也辛苦啦。”
* “帮我生成 3 条礼貌但不生硬的回复。”

---

### 3.4 用户类型 C：回复检查型用户

用户特点：

* 已经写了韩语回复；
* 不确定是否自然、礼貌、太直接或语气不合适；
* 希望系统评价并给出替代表达。

典型需求：

* “我这句回复自然吗？”
* “这个说法会不会太生硬？”
* “有没有更像粉丝回复 idol 的表达？”

---

## 4. V1 用户故事 / Use Cases

### 4.1 Feedback Chat 用户故事

作为韩语学习者，
我希望在看完 AI 解析后继续提问，
以便更深入理解某个词尾、语气或整段聊天含义。

### 4.2 AI 例句用户故事

作为学习者，
我希望保存学习卡片时自动生成例句，
以便我不仅知道这个词/语法是什么意思，也知道它如何在新句子中使用。

### 4.3 同时检查我的回复用户故事

作为用户，
我希望在学习解析 idol 消息的同时，也能检查我已经发出的韩语回复，
以便知道我的表达是否自然，是否需要修改。

### 4.4 快速回复建议用户故事

作为粉丝，
我希望不进入完整学习解析，也能快速生成韩语回复建议，
以便在 bubble / DM 场景中更快、更自然地回复 idol。

### 4.5 语气选择用户故事

作为用户，
我希望生成回复时可以选择自然、可爱、礼貌、朋友感或暧昧感，
以便根据聊天氛围得到不同风格的韩语回复。

# 6.1 学习卡片 AI 例句生成

## 6.1.1 功能描述

V1 需要补齐学习卡片中的 AI 例句生成能力。

当前 MVP 中，学习卡片已经可以保存生词和语法点，但 AI 例句尚未真正实现。V1 中，用户生成卡片时，系统应自动补充例句。

---

## 6.1.2 生词卡片例句

生词卡片需新增或补齐：

* AI 生成韩语例句；
* 中文翻译；
* 例句应符合该词的真实用法；
* 例句难度应适合初中级韩语学习者；
* 尽量贴近聊天语境。

示例：

```json
{
  "word": "응원하다",
  "meaning_zh": "应援，支持",
  "example_sentence": "항상 너를 응원하고 있어.",
  "example_translation_zh": "我一直都在支持你。"
}
```

---

## 6.1.3 语法 / 词尾卡片例句

语法卡片需新增或补齐：

* 1–2 条韩语例句；
* 每条例句附中文翻译；
* 例句应体现该语法点的语气；
* 需要说明适合什么关系 / 场景。

示例：

```json
{
  "point": "-잖아",
  "meaning_zh": "不是……嘛 / 你也知道……",
  "example_sentences": [
    {
      "ko": "우리 친구잖아.",
      "zh": "我们不是朋友嘛。"
    },
    {
      "ko": "내가 말했잖아.",
      "zh": "我不是说过了嘛。"
    }
  ]
}
```

---

## 6.1.4 例句生成规则

* 不要生成过难句子；
* 不要使用过于书面或考试化表达；
* 优先生成聊天语境中自然的句子；
* 不应包含敏感、暧昧过度或不适合粉丝场景的内容；
* 例句必须与词/语法点含义一致；
* 中文翻译应自然，不要机械直译。

---

# 6.2 Feedback Chat

## 6.2.1 功能描述

V1 在 **Analysis Result 页面底部** 增加统一 Feedback Chat 输入框。

用户可以对本次 AI 解析结果继续提问。

---

## 6.2.2 入口位置

入口放在 Analysis Result 页面底部。

不在每个气泡、生词、语法点旁边单独放按钮，以保持 UI 轻量。

页面底部可显示：

```text
还有哪里不懂？继续问我
[输入框：例如“这里为什么用 -는데？”]
[发送]
```

---

## 6.2.3 支持提问范围

Feedback Chat 需要支持用户围绕以下对象提问：

1. 整张截图 / 整段对话；
2. 某个原文气泡；
3. 某个生词；
4. 某个语法 / 词尾；
5. 某个语气标签；
6. 多条气泡是否应该连起来理解。

示例问题：

* “这里为什么用 -는데？”
* “这几条是不是应该连起来看？”
* “这个语气算可爱吗？”
* “-잖아 和普通陈述有什么区别？”
* “这句话适合我回复 idol 吗？”

---

## 6.2.4 Feedback Chat 上下文

V1 中，Feedback Chat 应使用当前 Analysis Result 作为上下文，包括：

* 原始气泡；
* 中文翻译；
* 生词解释；
* 语法解释；
* 语气标签；
* 用户标记 idol / 对方侧；
* 如有，当前我方回复评价结果。

---

## 6.2.5 V1 限制

V1 Feedback Chat 不做：

* 不保存完整 chat 历史；
* 不支持将追问结果生成新学习卡片；
* 不做复杂长期 tutor 记忆；
* 不进入用户学习画像。

这些进入 Future。

# 6.3 同时检查我的回复

## 6.3.1 功能描述

V1 中，用户在 OCR 确认页选择 idol / 对方侧后，系统可以将另一侧识别为“我”的回复侧。

在用户点击 **学习解析** 时，系统可同时完成：

1. 分析 idol / 对方气泡；
2. 检查我方气泡是否自然。

---

## 6.3.2 开关逻辑

在 OCR 确认页或学习解析按钮附近显示轻量开关：

```text
☑ 同时检查我的回复
```

默认逻辑：

> 如果截图中检测到我方韩语气泡，则默认开启；否则不显示。

对应你选择的方案：**C**

---

## 6.3.3 处理逻辑

当开关开启时：

* idol / 对方侧气泡：执行学习解析；
* 我方气泡：执行回复评价；
* 两类结果统一展示在 Analysis Result 页面。

---

## 6.3.4 我方回复评价输出

对于每条我方回复，输出两种状态之一。

### 状态 A：表达自然

显示：

* 原句；
* 评价：表达自然；
* 简短原因。

示例：

```text
我的回复：
오늘도 수고했어요!

评价：
这句表达自然，没有明显问题。语气礼貌、温柔，适合粉丝回复 idol。
```

---

### 状态 B：可以优化

显示：

* 原句；
* 问题解析；
* 更自然替代表达；
* 替代表达中文意思；
* 复制按钮。

示例：

```text
我的回复：
나는 너를 많이 좋아해요

问题：
意思可以理解，但在粉丝回复 idol 的语境中稍微有点直接。

更自然的说法：
항상 응원하고 있어요!

中文：
我一直都在为你应援！
```

---

## 6.3.5 回复评价原则

AI 评价应保持温和，不要让用户感到被批评。

避免使用：

* “你这句是错的”
* “表达很差”
* “不应该这样说”

推荐使用：

* “这句可以更自然一点”
* “意思能理解，但语气稍微有点直接”
* “如果想更像自然粉丝回复，可以这样说”

---

# 6.4 快速回复建议

## 6.4.1 功能描述

V1 新增独立的 **快速回复建议** 路径。

该路径不依赖完整 AI Analysis 学习流程，适合用户快速生成韩语回复。

---

## 6.4.2 入口

V1 包含两个入口：

### 入口 A：首页快速实时回复

首页新增入口：

```text
快速实时回复
```

用户可以从首页直接进入 Reply Suggestion 流程。

适用场景：

* 用户只想快速生成一句韩语回复；
* 不想完整上传截图并做学习解析；
* 可以直接粘贴 idol 原文或输入中文想说的话。

---

### 入口 B：OCR 确认页

用户上传截图 / 粘贴文本后，进入 OCR 气泡确认页。

在确认页底部，与 **学习解析** 并列提供：

```text
学习解析
生成回复建议
```

适用场景：

* 用户已上传聊天截图；
* 系统已经识别左右气泡；
* 用户可勾选想回复的 idol 气泡；
* 直接生成回复建议。

---

## 6.4.3 快速回复输入方式

V1 支持双入口输入：

### 方式 A：上传截图

流程：

```text
首页快速实时回复
→ 上传截图
→ OCR 识别左右气泡
→ 用户选择 idol 侧
→ 用户勾选要回复的 idol 气泡
→ 填写可选配置
→ 生成回复
```

### 方式 B：粘贴文本

流程：

```text
首页快速实时回复
→ 粘贴 idol 原文 / 对话文本
→ 用户填写可选中文想表达内容
→ 选择回复语气
→ 生成回复
```

---

## 6.4.4 回复建议输入项

Reply Suggestion 页面需要支持：

1. **选择要回复的 idol 气泡**

   * 可单选；
   * 可多选；
   * 如果从粘贴文本进入，则使用文本作为回复上下文。

2. **中文想表达的内容**

   * 可选；
   * 用户可以输入自己想说的话；
   * 例如：“今天也辛苦啦，要好好吃饭”。

3. **回复语气**

   * 必选或默认选择；
   * 选项：

     * 自然
     * 可爱
     * 礼貌
     * 朋友感
     * 暧昧感

4. **输出数量**

   * 默认 3 条；
   * V1 可以固定为 3 条，不一定开放用户修改。

---

## 6.4.5 回复建议输出

默认生成 3 条韩语回复。

每条回复包含：

* 韩语回复；
* 中文意思；
* 简单语气说明；
* 复制按钮。

示例：

```text
1. 오늘도 너무 수고했어요! 밥 꼭 챙겨 먹어요 💗
中文：今天也辛苦啦！一定要好好吃饭哦。
语气：可爱、关心感

[复制]
```

---

## 6.4.6 回复建议生成规则

AI 应遵守：

* 韩语自然；
* 不过度亲密；
* 避免冒犯或过度暧昧；
* 保持粉丝与 idol 语境的边界；
* 如果选择“暧昧感”，也应控制在轻微心动、不过线的表达；
* 不生成攻击、骚扰、过度私人化内容；
* 尽量短句、适合聊天发送。

---

# 6.5 单次截图内容限制

## 6.5.1 功能描述

为了保证 OCR、AI 分析速度和结果质量，V1 应增加单次截图内容限制提示。

---

## 6.5.2 推荐限制

* 单张截图建议不超过 **10 条聊天气泡**；
* 如果识别超过 **12 条气泡**，提示用户内容较多；
* 用户可以继续，但系统提示解析可能更慢；
* 如果内容过长，可建议裁剪截图或分批上传。

---

## 6.5.3 提示文案

当气泡数量较多时：

```text
这张截图内容有点多，解析可能会变慢。建议裁剪成 10 条以内的聊天内容，或分批上传。
```

按钮：

* 继续解析；
* 重新上传。

---

## 6.5.4 性能目标

V1 延续 MVP 性能目标：

| 场景            | 目标                 |
| ------------- | ------------------ |
| 学习解析          | 30 秒内返回结果          |
| 快速回复建议        | 10–20 秒内返回结果       |
| 超时阈值          | 超过 60 秒视为异常，需要提示重试 |
| Feedback Chat | 10–20 秒内返回回答       |

## 8. AI 输出与 Prompt 要求

---

# 8.1 学习卡片例句 Prompt 要求

AI 需要输出：

* 生词例句；
* 生词例句中文翻译；
* 语法例句；
* 语法例句中文翻译；
* 例句语气自然；
* 适合初中级学习者。

---

# 8.2 Feedback Chat Prompt 要求

AI 回答需要：

* 基于当前 analysis context；
* 不编造截图中没有的信息；
* 用中文解释；
* 韩语例子要准确；
* 对语气和关系判断保持谨慎；
* 不过度暧昧化；
* 如果不确定，明确说明“不确定”。

---

# 8.3 我的回复检查 Prompt 要求

AI 需要判断：

* 是否自然；
* 是否礼貌；
* 是否过于直接；
* 是否符合粉丝回复 idol 语境；
* 是否有语法或词尾问题；
* 是否需要替代表达。

输出结构建议：

```json
{
  "reply_text": "오늘도 수고했어요!",
  "status": "natural",
  "feedback_zh": "这句表达自然，没有明显问题。",
  "suggested_reply": null,
  "suggested_reply_zh": null
}
```

如果需要优化：

```json
{
  "reply_text": "나는 너를 많이 좋아해요",
  "status": "needs_improvement",
  "feedback_zh": "意思能理解，但在粉丝回复 idol 的语境中稍微有点直接。",
  "suggested_reply": "항상 응원하고 있어요!",
  "suggested_reply_zh": "我一直都在为你应援！"
}
```

---

# 8.4 Reply Suggestion Prompt 要求

输入：

* idol 原文 / 被选气泡；
* 可选中文意图；
* 回复语气；
* 输出数量：3。

输出：

```json
{
  "suggestions": [
    {
      "reply_ko": "오늘도 너무 수고했어요! 밥 꼭 챙겨 먹어요 💗",
      "reply_zh": "今天也辛苦啦！一定要好好吃饭哦。",
      "tone": "可爱 / 关心",
      "note_zh": "语气温柔可爱，适合粉丝回复 idol。"
    }
  ]
}
```

要求：

* 默认生成 3 条；
* 不要生成过长回复；
* 不要过度亲密；
* 不要生成可能冒犯 idol 或越界的表达；
* 韩语要自然；
* 中文解释要简洁。

## 9. 非功能需求

---

# 9.1 性能需求

| 功能            | 目标          |
| ------------- | ----------- |
| 学习解析          | 30 秒内返回     |
| 快速回复建议        | 10–20 秒内返回  |
| Feedback Chat | 10–20 秒内返回  |
| 超时处理          | 超过 60 秒提示重试 |
| 单张截图          | 建议 10 条以内气泡 |

---

# 9.2 隐私需求

V1 延续 MVP 隐私原则：

* 不长期保存原始截图；
* 不保存完整解析历史；
* 学习卡片本地保存；
* Feedback Chat V1 不保存长期历史；
* 快速回复建议不默认保存；
* 用户输入的中文意图不默认保存；
* AI 调用前应在隐私说明中提示文本可能被发送给模型服务处理。

---

# 9.3 易用性需求

* Reply Suggestion 不能藏太深；
* 学习解析和快速回复路径需要清晰区分；
* “同时检查我的回复”必须是轻量开关；
* 不应让用户反复确认太多步骤；
* Feedback Chat 入口要轻，不干扰学习解析主页面；
* 语气选项应简单直接。

---

# 9.4 安全与边界

回复建议需要避免：

* 过度暧昧；
* 骚扰式表达；
* 过度私人化；
* 冒充亲密关系；
* 不适合 fan-idol 边界的内容；
* 攻击性或冒犯内容。

对于“暧昧感”语气：

* 应限制为轻微心动、可爱、含蓄；
* 不生成露骨或越界表达；
* 可以提示用户“该语气可能不适合所有场景”。

## 10. 成功指标

### 10.1 V1 核心指标

| 指标                   | 目标                                 |
| -------------------- | ---------------------------------- |
| 学习卡片完整率              | 90%+ 新生成卡片包含 AI 例句                 |
| Reply Suggestion 使用率 | 使用过 OCR/粘贴流程的用户中，至少 30% 尝试快速回复     |

| Feedback Chat 使用率    | 查看 Analysis Result 后，至少 15% 用户发起追问 |
| 回复检查完成率              | 检测到我方气泡且开关开启时，80%+ 能生成评价           |
| 性能                   | 快速回复建议 10–20 秒内返回，学习解析 30 秒内返回     |

---

### 10.2 体验指标

可通过用户测试收集：

* 用户是否理解学习解析和快速回复的区别；
* Feedback Chat 是否真的解决疑问；
* 回复建议是否自然；
* “暧昧感 / 朋友感 / 可爱”语气是否符合预期；
* 我方回复评价是否温和、不冒犯；
* 卡片例句是否有学习价值。

## 13. V1 总结

V1 的核心升级是：

> 从“读懂 idol 聊天”进一步变成“读懂后能继续问、能检查自己回复、能快速生成自然韩语回复，并把学习卡片补充完整”。

V1 的主要功能是：

1. **学习卡片 AI 例句生成**；
2. **Analysis Result 页面底部 Feedback Chat**；
3. **学习解析时可同时检查我的回复**；
4. **独立快速回复建议路径**；
5. **首页和 OCR 确认页双入口 Reply Suggestion**；
6. **单次截图气泡数量提示与性能优化**。

V1 不把 Audio pronunciation、User learning profile、Textbook wordbook import 放入正式范围，而是作为后续版本规划。
