# PRD 草案：오늘의 시그널 / Today’s Signal

## 韩语聊天截图学习助手 iOS App

---

## 1. 引言 / 概述

### 1.1 产品名称

**오늘의 시그널 / Today’s Signal**

### 1.2 产品类型

iOS 移动端 App

### 1.3 一句话定位

**帮助 K-pop / 韩娱粉丝读懂韩语聊天截图中的词汇、语法和语气，并把真实聊天表达沉淀成学习卡片的 iOS App。**

### 1.4 产品背景

许多韩语学习者，尤其是 K-pop / 韩娱粉丝，会接触 idol bubble、DM、社交平台评论或聊天截图等真实韩语内容。相比教材中的标准句子，这些内容往往更口语化，包含大量平语、缩写、词尾变化、语气符号、emoji、`ㅋㅋ`、`ㅠㅠ` 等表达。

用户的痛点不是单纯“不认识单词”，而是：

* 不理解聊天里的真实语气；
* 不知道词尾如 `-어`, `-다`, `-잖아`, `-는데`, `-지` 在具体语境中的作用；
* 不确定某句话是普通陈述、可爱语气、吐槽、关心还是冷淡；
* 想从 idol / 韩娱聊天内容中自然积累生词和语法；
* 想知道自己回复的韩语是否自然。

因此，本产品希望把“看聊天截图”转化为一个轻量、真实语境驱动的韩语学习流程。

---

## 2. 目标 / 目的

### 2.1 产品目标

MVP 的核心目标是：

1. **帮助用户更快看懂韩语聊天截图内容**
   让用户在上传截图或粘贴文本后，快速获得中文自然翻译、生词解释和语法/词尾解释。

2. **帮助用户从真实聊天语境中积累韩语表达**
   用户可以将不认识的生词和语法点生成学习卡片，而不是只看一次翻译。

3. **保留聊天语气理解能力，但不过度扩展**
   MVP 保留轻量语气标签，例如普通陈述、亲近随意、可爱/撒娇、吐槽/开玩笑等，但不重点做暧昧程度判断或复杂文化语境分析。

4. **提供可控、隐私友好的本地学习体验**
   MVP 不做账号系统、不做云同步，学习卡片和用户标记记录默认保存在本地。

### 2.2 SMART 化目标

MVP 阶段建议目标：

| 目标类型 | 指标                                    |
| ---- | ------------------------------------- |
| 解析速度 | 用户确认文本后，30 秒内看到解析结果；超过 60 秒视为异常或需要优化  |
| 学习沉淀 | 用户每次解析后平均保存 1–3 张学习卡片                 |
| 输入范围 | 支持单张聊天截图，优先处理 10 条以内短消息               |
| 用户流程 | 用户可以完成“上传/粘贴 → 确认文本 → 查看解释 → 生成卡片”的闭环 |
| 隐私   | 不长期保存原始截图，不保存完整解析历史                   |

## 3. 目标受众 / 用户画像

### 3.1 核心目标用户

**K-pop / 韩娱粉丝中的初中级韩语学习者**

用户特征：

* 会一点韩语，可能学过基础语法和敬语；
* 能认识部分常见词，但经常不理解聊天中的词尾、语气和缩写；
* 经常看 idol bubble、DM、Weverse、X、Instagram、粉丝搬运截图等内容；
* 希望通过真实聊天内容学习更自然的韩语表达；
* 对“语气是否自然”“这句话怎么理解”比较敏感。

### 3.2 典型用户画像

#### Persona 1：追星型韩语学习者

* 用户：K-pop 粉丝，正在自学韩语；
* 场景：看到 idol 发来的 bubble 消息，不想只依赖机器翻译；
* 痛点：翻译能看懂大意，但不知道词尾和语气为什么这么用；
* 需求：想知道这句话里哪些词值得学、语气是什么、能不能保存成学习卡片。

#### Persona 2：想回复 idol 的用户

* 用户：会写一些简单韩语，但不确定表达是否自然；
* 场景：想给 idol 回复一句韩语；
* 痛点：担心自己写得太生硬、不礼貌或不像自然聊天；
* 需求：希望 App 能轻量检查自己的回复，如果有问题给出替代表达。

#### Persona 3：韩娱内容阅读型用户

* 用户：常看韩娱社交平台评论、聊天截图、搬运内容；
* 场景：看到韩语评论或聊天内容；
* 痛点：普通翻译无法解释语气、梗感、词尾；
* 需求：希望按句拆解并学习真实表达。

## 4. 用户故事 / 使用场景

### 4.1 核心用户故事

#### 用户故事 1：上传 idol 聊天截图并学习表达

作为一名 K-pop 粉丝，
我希望上传一张 idol bubble / DM 聊天截图，
以便快速理解每条消息的中文意思、生词和语法点。

#### 用户故事 2：确认 OCR 识别文本

作为用户，
我希望系统 OCR 后能按气泡展示识别出的文字，并允许我编辑，
以便避免识别错误影响后续 AI 解释。

#### 用户故事 3：查看逐条聊天解释

作为初中级韩语学习者，
我希望每条聊天气泡都有固定结构的解释，
包括中文自然翻译、生词、语法/词尾和简单语气标签。

#### 用户故事 4：标记认识/不认识的知识点

作为学习者，
我希望对每个生词或语法点选择“认识”“不认识但不生成卡片”或“不认识并生成卡片”，
以便控制自己的学习负担。

#### 用户故事 5：生成学习卡片

作为用户，
我希望对不认识的词或语法点生成学习卡片，
以便之后在卡片库中复习。

#### 用户故事 6：检查自己的韩语回复

作为想回复 idol 的用户，
我希望系统能简单检查我写的韩语回复是否自然，
如果不自然，希望看到问题说明和替代表达。

## 6. 功能需求

---

### 6.1 首页输入页

#### 功能描述

首页采用极简设计，提供两个主要入口：

1. 上传截图；
2. 粘贴文本。

#### 页面内容

* 产品名：오늘의 시그널 / Today’s Signal；
* 副标题：韩语聊天截图学习助手；
* 主按钮：上传聊天截图；
* 次按钮：粘贴韩语文本；
* 简短说明：上传截图后，App 会帮你识别聊天内容、解释韩语表达，并生成学习卡片。

#### 需求细节

* 用户可以从相册选择截图；
* 用户可以直接粘贴文本；
* 如果用户上传非聊天截图，应提示重新上传或粘贴文本。

---

### 6.2 OCR 与气泡识别

#### 功能描述

用户上传截图后，系统使用 OCR 提取文字，并尽量按聊天气泡结构拆分。

#### 识别规则

* 优先识别气泡内文本；
* 气泡内的内容全部保留，包括：

  * 韩语；
  * 中文 / 英文混杂内容；
  * emoji；
  * `ㅋㅋ`、`ㅠㅠ`；
  * 标点；
  * 换行。
* 图片气泡不做图像内容理解，显示为 `[图片]`；
* 用户名、时间戳、已读状态、按钮等非核心元素尽量过滤或不展示。

#### 异常处理

* 如果气泡识别成功：按气泡展示；
* 如果气泡识别失败：降级为按行展示文本；
* 如果没有识别到可解析的韩语聊天内容：提示“未识别到可解析的韩语聊天内容，请重新上传截图或粘贴文本”。

---

### 6.3 文本确认页

#### 功能描述

OCR 后进入文本确认页，用户可以逐条确认和编辑气泡内容。

#### 页面内容

* 按聊天气泡或按行展示识别结果；
* 每条内容可编辑；
* 图片内容显示为 `[图片]`；
* 用户可以删除无关气泡或无关文本；
* 用户可以标记哪一侧是 idol / 对方。

#### 角色标记

支持用户选择：

* 左侧是对方；
* 右侧是对方。

如果用户不标记，系统可以默认解析所有韩语气泡，但推荐用户标记以获得更清晰结果。

#### 需求目的

文本确认页的目标是降低 OCR 错误对 AI 解析结果的影响。

---

### 6.4 AI 解析结果页

#### 功能描述

确认文本后，系统调用 AI 对聊天气泡进行解析。

默认主要解析 **idol / 对方气泡**，并从对方气泡中提取学习点。

#### 展示方式

解析结果页按气泡逐条展示：

每条气泡下方展开：

1. 原句；
2. 中文自然翻译；
3. 语气标签；
4. 重点生词；
5. 重点语法 / 词尾。

#### 固定输出结构

每条气泡的 AI 输出结构应保持一致，便于前端展示和用户操作。

示例结构：

```json
{
  "original_text": "오늘 뭐해?",
  "translation_zh": "今天在干嘛？",
  "tone_label": "亲近随意",
  "vocabulary": [
    {
      "word": "오늘",
      "meaning_zh": "今天",
      "pronunciation": "오늘 [오늘]",
      "part_of_speech": "名词/副词",
      "usage_note": "表示今天，聊天中常用于开启话题"
    }
  ],
  "grammar_points": [
    {
      "point": "-해?",
      "meaning_zh": "做……吗？",
      "tone_note": "平语疑问句，语气自然亲近",
      "usage_context": "适合朋友、熟人、亲近关系中使用"
    }
  ]
}
```

#### 语气标签

MVP 使用固定标签集合，避免 AI 输出过于发散。

建议标签：

1. 普通陈述；
2. 亲近随意；
3. 可爱 / 撒娇；
4. 吐槽 / 开玩笑；
5. 安慰 / 关心；
6. 礼貌表达；
7. 冷淡 / 简短。

#### 生词与语法提取规则

* 不设置硬性数量限制；
* 但 prompt 应要求 AI 只提取对初中级学习者有学习价值的重点内容；
* 如果某条气泡提取过多知识点，应视为 prompt 或模型输出异常，需要优化。

---

### 6.5 自己回复检查

#### 功能描述

如果截图中包含用户自己的韩语回复，系统可以进行轻量检查。

#### 规则

* 不对自己的回复做完整生词/语法拆解；
* 不默认从自己的回复中生成卡片；
* 主要判断表达是否自然。

#### 输出逻辑

如果没有问题：

> 这句表达自然，没有明显问题。

如果有问题：

* 说明问题；
* 给出更自然的替代表达。

示例：

```json
{
  "my_reply": "나는 너를 많이 좋아해요",
  "status": "needs_improvement",
  "issue_zh": "表达本身没有错，但在粉丝回复 idol 的语境里可能稍显直接。",
  "suggested_reply": "항상 응원하고 있어요!",
  "suggested_reply_zh": "我一直都在为你应援！"
}
```

---

### 6.6 知识点操作

#### 功能描述

用户可以对每个生词和语法点进行学习状态标记。

#### 操作选项

每个知识点提供三个操作：

1. **认识**
   用户已掌握该知识点，不生成卡片。

2. **不认识，但不生成卡片**
   用户想看解释，但暂时不想加入卡片库。

3. **不认识，生成卡片**
   系统生成对应学习卡片，并保存到卡片库。

#### 本地记录

MVP 本地记录：

* 用户标记过“认识”的知识点；
* 用户标记过“不认识但不生成卡片”的知识点；
* 用户生成的学习卡片。

对于已标记“认识”的知识点，后续解析时可以尽量减少重复展示。该逻辑属于轻量个性化，不作为复杂用户画像系统。

---

### 6.7 生词卡片

#### 功能描述

用户选择“不认识，生成卡片”后，系统为生词生成学习卡片。

#### 生词卡片字段

* 韩语原词；
* 中文意思；
* 原聊天句子；
* AI 生成的新例句；
* 发音标注，例如 `번역 [버녁]`；
* 词性或用法说明。

#### 示例

```json
{
  "type": "vocabulary",
  "word": "번역",
  "meaning_zh": "翻译",
  "pronunciation": "번역 [버녁]",
  "original_sentence": "이거 번역해줄 수 있어?",
  "example_sentence": "한국어 문장을 중국어로 번역했어요.",
  "example_translation_zh": "我把韩语句子翻译成了中文。",
  "part_of_speech": "名词",
  "usage_note": "常用于表示翻译文本或语言内容。"
}
```

---

### 6.8 语法 / 词尾卡片

#### 功能描述

用户选择“不认识，生成卡片”后，系统为语法点或词尾生成学习卡片。

#### 语法卡片字段

* 语法点名称；
* 中文含义；
* 语气说明；
* 原聊天句子；
* 1–2 个新例句；
* 适合什么关系 / 语境使用。

#### 示例

```json
{
  "type": "grammar",
  "point": "-잖아",
  "meaning_zh": "不是……嘛 / 你也知道……",
  "tone_note": "带有提醒、强调或拉近关系的语气。",
  "original_sentence": "나 어제 말했잖아.",
  "example_sentences": [
    {
      "ko": "우리 친구잖아.",
      "zh": "我们不是朋友嘛。"
    },
    {
      "ko": "그거 내가 했잖아.",
      "zh": "那个不是我做的嘛。"
    }
  ],
  "usage_context": "常用于熟人、朋友、亲近关系中。正式场合需谨慎使用。"
}
```

## 7. 非功能需求

---

### 7.1 性能需求

| 场景       | 要求                      |
| -------- | ----------------------- |
| 单张截图 OCR | 应在可接受时间内完成，避免明显卡顿       |
| AI 解析    | 用户确认文本后，目标 30 秒内返回结果    |
| 超时判断     | 超过 60 秒视为异常，需要提示用户或支持重试 |
| 截图长度     | MVP 优先支持 10 条以内短消息      |

---

### 7.2 准确性需求

#### OCR 准确性

* 大多数清晰截图应能自动识别主要聊天文本；
* 允许用户手动修正；
* 不追求 100% 自动正确，而是追求“自动初稿足够好 + 用户可快速修正”。

#### 气泡识别准确性

* 大多数清晰聊天截图应能较准确拆分气泡；
* 失败时降级为按行展示；
* 用户可手动编辑和删除错误内容。

#### AI 解释准确性

* 输出应保持固定结构；
* 不应编造原文中不存在的内容；
* 生词和语法解释应贴合原句；
* 语气标签应从固定集合中选择；
* 对不确定内容应避免过度解释。

---

### 7.3 隐私与数据安全

MVP 需要明确隐私边界。

#### 数据保存原则

保存：

* 生词卡片；
* 语法 / 词尾卡片；
* 用户标记过的“认识”知识点；
* 用户标记过的“不认识但不生成卡片”知识点。

不保存：

* 原始截图；
* 完整解析历史；
* 完整聊天上下文；
* 用户账号信息。

#### 用户提示

App 应提醒用户：

* 不要上传包含敏感个人信息的截图；
* AI 解析可能需要将用户确认后的文本发送给外部模型服务；
* 原始截图不做长期保存；
* 学习卡片和标记记录默认保存在本地设备。

#### 后续功能隐私要求

如果未来加入：

* 云同步；
* 学习画像；
* 多设备同步；
* Share Extension；
* 账号系统；

需要单独说明数据用途，并征得用户授权。

---

### 7.4 易用性需求

* 首页入口清晰，用户能快速开始；
* OCR 后必须有确认/编辑步骤；
* 解析结果按气泡逐条展示；
* 学习操作按钮清晰，不让用户被迫生成卡片；
* 卡片字段不宜过度复杂；
* 视觉风格应可爱但不影响阅读效率。

---

### 7.5 稳定性与错误处理

#### 非韩语聊天截图

提示：

> 未识别到可解析的韩语聊天内容，请重新上传截图或粘贴文本。

#### OCR / 气泡识别失败

* 保留 OCR 结果；
* 降级为按行展示；
* 用户可继续编辑后解析。

#### AI 部分解析失败

* 展示成功解析的气泡；
* 失败气泡提供单独重试；
* 保留用户已确认文本。

#### AI 超时

* 提示用户解析超时；
* 提供重新解析按钮；
* 不清空用户已确认文本。

## 9. 成功指标

* 语气标签是否准确；
* 卡片内容是否值得保存；

## 10. 技术假设

MVP 默认技术路径：

* 前端：SwiftUI；
* OCR：Apple Vision / VisionKit；
* AI 解析：外部 LLM API；
* 数据存储：iOS 本地存储；

### 10.1 技术重点

1. OCR 韩语识别；

3. AI 结构化输出；
4. 本地卡片存储；

### 10.2 AI Prompt 关键要求

* 只支持韩语 → 中文解释；
* 输出固定 JSON 结构；
* 每条气泡包含原句、中文自然翻译、语气标签、重点生词、重点语法/词尾；
* 语气标签必须从固定集合选择；
* 只提取对初中级用户有学习价值的重点内容；
* 不要过度解释；
* 不要编造原文中没有的信息。

## 12. 当前 MVP 总结

**오늘의 시그널 / Today’s Signal** 的 MVP 是一个面向 K-pop / 韩娱粉丝的 iOS 韩语聊天截图学习助手。

它的核心闭环是：

> 上传截图 / 粘贴文本
> → OCR 并按气泡拆分
> → 用户确认文本和对方气泡
> → AI 逐条解释韩语聊天内容
> → 用户标记认识/不认识
> → 不认识的内容生成学习卡片
> → 本地保存到卡片库

MVP 的重点不是做一个完整翻译器，也不是做一个聊天代写工具，而是：

**让真实韩语聊天内容变成可理解、可积累、可复习的学习材料。**
